Technical Overview

CapNet — Where It's Heading

The capability layer for AI agents. Scoped, revocable, auditable authority — enforced at the boundary where actions happen.
"Leash, not master keys."
The Problem

Agents are becoming a new class of actor on the internet

AI agents are moving beyond conversation. They turn natural language into real-world side effects — spending money, accessing accounts, deploying code, managing infrastructure. They operate at machine speed and machine scale. The distance between intent and action is collapsing, and that gap is where safety used to live.

Today, to let an agent act, you hand it your credentials — passwords, API keys, OAuth tokens. These are effectively master keys. If the agent is compromised, the attacker gets everything the agent can reach. There's no way to say "you can spend up to $200 at these three vendors, only on weekdays, and I can kill it instantly."

The internet solved transport. AI is solving cognition. Nobody has solved governable authority for machine actors. That's CapNet.

Critical Distinction

What CapNet is NOT

This matters more than what it is. Getting this wrong kills the pitch.

CapNet is none of these things:

Not a firewall. A firewall monitors all traffic — yours, your agent's, everyone's. CapNet only governs the agent. The human can still do whatever they want.
Not surveillance or DLP. CapNet doesn't watch your browsing, scan your data, or filter your content.
Not a prompt-based restriction. CapNet doesn't ask the AI "please don't buy alcohol." The agent can try anything it wants — a separate enforcement proxy blocks what the capability doesn't allow. A prompt is a suggestion. A capability is a physical boundary.
Not a payments company. Spending is the demo wedge, not the product.
Not an LLM wrapper. CapNet is infrastructure that works with any agent framework.
Not blockchain. Cryptographic signatures, not distributed consensus.
The analogy isn't a firewall. It's power of attorney with limits — you authorize someone to act on your behalf, but only within specific bounds, and you can revoke it instantly. "A fence for the agent, not a cage for the user."

The enforcement proxy runs a 7-step pipeline on every action: signature → executor binding → time window → revocation check → vendor → category → budget. Any check fails, the action is denied. The agent never touches raw credentials.

The Full Architecture

Three layers, building toward a closed loop

LAYER 1 — CRYPTOGRAPHIC ENFORCEMENT Built

Hard Boundaries

Every agent action passes through a proxy that enforces signed capability tokens. Each token defines exactly what the agent can do: budget limits, vendor restrictions, time windows, category constraints, executor binding to the agent's cryptographic identity. The proxy runs a deterministic 7-step enforcement pipeline. If any check fails, the action is blocked. The user holds a hardware-bound kill switch — instant revocation, no negotiation. Every action produces a signed receipt for the audit trail. This is the foundation everything else builds on.

LAYER 2 — BEHAVIORAL INTELLIGENCE Planned

Smart Baselines

Static rules aren't enough. An agent with a $10,000 travel budget booking 47 one-way tickets to different countries is clearly compromised — but each individual action is within policy. The behavioral layer watches patterns, not just individual actions. It builds baselines of normal activity: time-of-day patterns, frequency, velocity, geographic distribution, vendor mix, amount curves. When behavior deviates, the system flags or auto-pauses before damage compounds. It also generates policies intelligently — instead of users hand-writing permission templates, the system observes the agent's intended purpose and suggests appropriate constraints. Users review and approve, rather than author from scratch.

LAYER 3 — PROOF-OF-CLAIM VERIFICATION Vision

Verified Outcomes

Layers 1 and 2 govern what an agent is allowed to do. Layer 3 verifies what actually happened. The Proof-of-Claim Layer is a protocol where real-world claims are published with evidence, staked by attestors who put reputation and money on the line, corroborated by independent sources, and composed into queryable confidence scores. Did the agent's actions produce the outcomes it reported? Every claim carries: who made it, what evidence supports it, what's at stake if it's false, and who else independently confirms it. It doesn't assert truth — it asserts confidence with provenance and consequence.

Layer 1 checks if the action is permitted. Layer 2 checks if the pattern is normal. Layer 3 checks if the outcome is real.

Why these layers form a closed loop

The behavioral intelligence layer needs a ground truth signal to know whether an agent's actions actually produced legitimate outcomes. That's exactly what the Proof-of-Claim Layer provides. The attestation feed becomes training data for anomaly detection.

An agent that books a hotel and a verified check-in attestation confirms the stay? That agent is building a trustworthy behavioral profile. An agent that books hotels with no corresponding real-world verification? That's a flag.

Enforcement + intelligence + verification = a self-improving governance system.

The Stakes

Why this has to exist, and why now

Every major AI lab is shipping agents that can take real-world actions. None of them have solved governance. The current approach — agents with full account credentials — is a security catastrophe waiting to happen. The first major "agent gone rogue" headline will create massive demand for exactly this infrastructure.

OAuth answers "who are you?" — CapNet answers "what exactly can you do right now, and can I stop you?" They're different layers. CapNet isn't competing with OAuth or IAM. It's solving a problem that didn't exist until 2023.

The AI labs would rather adopt an open standard than build proprietary solutions that regulators will hate. The window to establish that standard is open right now.
